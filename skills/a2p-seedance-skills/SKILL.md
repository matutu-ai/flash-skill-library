# LingGuo Seedance Master

将用户给出的文字、客户资料、图片、视频或音频转为**可直接提交的 Seedance 提示词交付包**。先分析并确认创意方案，再完成素材、分镜和提示词；若用户已授权视频制作，则继续生成、审片、修复并交付视频，不重复询问同一授权。没有视频制作要求时，停在提示词交付。视频生成、后期预演和正式发布要分别标明，不能互相冒充。

## 第一阶段：分析资料并提交完整创意方案

1. 先读取用户提供的可访问文本、文档、图片、视频、音频或链接；图片看实际外观，视频看实际动作与结束状态，不能只凭文件名推断。提取**事实、目标、限制与待确认项**：产品或主题、受众与市场、传播目的、目标平台、时长、画幅、风格偏好、现有素材、声音与字幕要求。将资料中没有证据的卖点或效果与已确认事实分开。一般缺项采用标明的暂定值；只有缺失会改变创意路径的关键资料才提一个问题，不重复询问已提供信息。
2. **先定玩法，再定创意方向。** 判断可用生成方式：文生、图生、多素材参考、动作/运镜参考、首尾帧、故事板、音频驱动、多镜头、编辑、延长或组合。若用户要求从“八大玩法”中选择，在资料分析后先列出与素材匹配的 2–3 个编号玩法、各自需要的素材和控制重点，允许用户先选；分类见[八大玩法选择](references/eight-plays.md)。**每个展示供选择的玩法各配一张实际可查看的概念效果图**；展示全部八项时各配一张，共八张。优先基于用户素材制作，明确它是静态预览而非已生成的视频帧；预览图是否作为 Seedance 输入须在素材表另行绑定。八大玩法是案例分类，不等于平台官方模式，最终仍需映射到实际生成模式。若用户已选玩法，保留该选择并为其提供一张效果图；若未要求先选，推荐一个玩法并与创意方案一起供确认。另按[类型与配方](references/creative-recipes.md)选择内容主类型与最多两个辅助类型。
3. 在选定或推荐的玩法下，提出通常 2–3 个有实际区别的创意方向，每个说明核心概念、开头钩子、叙事/镜头方法、风格、所需素材和主要制作难点。推荐一个方向，并把它展开为可审核的完整方案：视频结构、镜头节拍、人物/产品与场景约束、声音方向、素材准备和最终交付范围。明确区分“玩法编号 1–8”与“创意方向 A/B/C”，不要把用户选 C 误当作玩法编号。
4. **到此暂停，等待尚未确认的选择。** 用户可先选玩法，再选方向，也可一次回复同时选择。已选玩法与方向、或已批准具体方案时，直接进入第二阶段；不得重复请求确认。[两阶段交付格式](references/production-and-delivery.md)。

## 第二阶段：确认后自主完成提示词包

1. 核对目标平台和模型的当前能力：任务模式、素材格式与数量、单次时长、比例、音频/人脸规则、引用语法。优先看该平台官方文档或实际界面；超出单次能力时改为可执行的分段方案，不把超限的单次提示词称作可直接提交。未核实引用语法时，用 `@图片1`、`@视频1`、`@音频1` 标明素材插入位置，并说明提交时用平台真实 token 替换。[平台与素材](references/platform-and-assets.md)。
2. 给已有素材分配职责、继承/不继承内容、作用镜头和优先级。缺什么才写什么：**一项待制作素材一条可复制的生成提示词或制作指令**。用户要求实际参考图时才制作；已有原图优先从可访问附件恢复并保留原件，无法取得则标为待补，不用生成图冒充。真实产品和企业事实以用户资料为准；生成图若改变产品细节，只能作构图/场景参考，不得覆盖产品原图。
3. 完成分镜：每镜头写目的、时段、起止状态、主体动作、景别/机位、一个主要运镜、光线、声音及素材绑定。多段项目记录**计划中的**连续状态；已有视频作为输入时，以实际画面状态为准。[分镜与交付](references/production-and-delivery.md)。
4. 编译**可直接复制的 Seedance 主提示词**。结合[结构化提示词模板](references/platform-and-assets.md#结构化视频提示词模板)：首行写 `【玩法】` 与实际生成方式；下一行写版本、时长、画幅和声音设置；再按素材职责与优先级、主体和空间锁定、按时间顺序的动作/镜头/声音、结束状态、必要禁止项组织。每项上传素材都在代码块内用 `@图片N`、`@视频N` 或 `@音频N` 绑定对象和镜头，末尾再列一次最终上传顺序。复杂动作分阶段写，转场交代前后可见状态；禁止项只保留会导致明显跑偏的变化，避免重复和冲突。需要分段时给每段独立可提交的提示词及接点。准确文字、数字、Logo 和 CTA 依赖真实素材或后期叠加，不能只要求模型拼字。[提示词优化要点](references/platform-and-assets.md#编译提示词)。
5. 导出实际要上传的素材：素材表同时列 token 与下载文件名，文件名以 `图片N-用途.png`、`视频N-用途.mp4` 等编号开头。多项素材备齐时，写 `素材清单.json`，运行 [打包脚本](scripts/package_assets.py) 生成并校验一个 ZIP，给用户一键下载链接；效果预览图等不上传的文件不入包。具体格式见[打包与交付](references/production-and-delivery.md#编号素材与一键下载)。
6. 自检并直接修正：事实依据、每个 `@素材` 与交付文件的一一对应、平台设置、镜头时间总和、起止状态、身份/产品/场景约束、声音与文字要求、提示词之间的矛盾。最终交付附简短自检结论和仍需确认的事实；已解决的问题不再转交用户。[自检标准](references/production-and-delivery.md#交付前提示词自检)。

## 输出尺度

第一阶段交付**完整创意方案**，第二阶段交付**素材绑定 → 素材生成提示词 → 分镜 → Seedance 主提示词 → 必要的分段提示词 → 提交设置 → 自检结论**。用户已要求视频时，再完成第三阶段。没有对应素材或无需分段时省略，不输出空模板。

- **普通创作**：按两阶段输出；用户仅要求润色一句现有提示词时按该窄范围直接完成。
- **企业项目**：保留客户展示版的创意与效果描述，以及内部制作版的素材编号、提示词、参数和事实依据。[分镜与交付](references/production-and-delivery.md)。
- **课堂演示**：用运营人员能照做的语言说明玩法、素材职责、参考图提示词、分镜与 Seedance 提示词。实际提交、结果分析和前后对比仅在用户要求课堂实操时进行。

## 必须守住的事实与连续性

- 卖点、产品结构、客户案例、品牌历史、认证与效果只能来自可核查资料；不要凭生成画面补造事实。
- 品牌名、Logo、准确文案与数字只有在已确认素材中才能当作正式内容；候选品牌须标为候选，精确字形优先使用原图或后期叠加。
- 参考图、动作视频、镜头视频和音频各有职责；写清继承与不继承的内容。图片姿态不能等同真实动作视频。
- 编辑仅改授权的对象和时间段；延长从原片实际结束状态继续，不重复已完成事件。人物、服装、产品、场景锚点、道具归属、运动方向与声音须按项目状态表检查。
- 物理真实感落实到重力、接触、惯性、遮挡、材质和运动结果；真人口播注意短句、停顿、眼神、微表情与轻手势。模型无法可靠保证的口型、文字或卡点交给合适的后期步骤。
- 原始素材和输出只在授权范围内使用；若平台对真人脸、声音、品牌或输入视频有额外限制，按当前平台规则处理。
- 当前会话中“可以做视频”“继续生成”等明确指令可授权进入视频制作，不再重复确认；发布、付款或向客户发送成片仍需相应授权。

## 第三阶段：已授权时制作视频

1. 按实际平台检查模型、输入规则、账户、费用和真人肖像素材的可用路径；素材被平台限制时先使用其支持的授权方案，不暗改人物身份。没有可用的 Seedance 生成入口时如实说明，不能把本地预演称作 Seedance 成片。[平台与素材](references/platform-and-assets.md)。
2. 用已核对的素材与最终提示词提交。若平台限制时长或参考数，按第二阶段的分段提示词执行；保存任务状态和可下载结果。视频链接有时效时及时下载到项目目录。
3. 逐镜检查人物和产品一致性、转场、道具连续性、文字/Logo、时长画幅、音画及结尾。针对可见问题修订主要变量并复测；交付可播放文件，说明实际模型、修复轮次和尚未验证的部分。[成片反馈](references/production-and-delivery.md#实际生成后的反馈已授权视频制作时使用)。
