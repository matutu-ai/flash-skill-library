01 / USE CASES

适合用来做什么

  • 企业 GEO 关键词规划
  • 企业与垂直业务画像生成
  • 内容矩阵与发布策略制定
  • GEO 验证与缺口分析

02 / PROMPT

Prompt 内容

使用 geo-keyword-profile-template 分析我提供的企业资料。先说明 GEO V3 框架、已有事实与资料缺口，再按正式流程生成简约版关键词和九大画像；不要虚构企业、案例、资质、数据或验证结果。

03 / WORKFLOW

执行流程

  1. 01

    清洗企业资料并区分事实、证据与缺失项

  2. 02

    建立企业 GEO Profile、行业研究与竞争研究

  3. 03

    生成搜索意图、关键词矩阵、九大画像与垂直画像

  4. 04

    规划内容矩阵与动态发布策略

  5. 05

    执行 GEO 验证、缺口分析、内容补强与再次验证

04 / HOW TO USE

使用方法

  1. 01
    准备输入

    企业介绍、产品或服务资料、案例、图片、docx、xlsx、文本或网页链接，以及用户的生成、调整、批量或验证指令。

  2. 02
    打开正式入口

    进入对应 GitHub 仓库，先阅读正式 Skill 入口和仓库内的配套文件。

  3. 03
    复制并填写 Prompt

    复制本页 Prompt，将其中的目标、资料和限制替换为当前任务的真实信息。

  4. 04
    按 Workflow 执行

    依次完成各步骤，并根据运行要求检查结果后再交付。

05 / PLATFORM USE

豆包、千问怎么使用

豆包

在豆包里上传技能和企业资料，按你的要求生成四类关键词、九大画像等 Markdown 交付物；缺资料就标「待补」，不编造。

  1. 打开豆包，新建对话；上传或粘贴本技能的 SKILL.md（或从技能页下载的技能包）。
  2. 切换模式：点豆包输入框左下角的「云电脑」，选「工作任务 · 云电脑」。
  3. 再上传企业资料：介绍、产品/服务说明、案例、表格（xlsx/docx）、图片或网页链接。
  4. 用一句话说清要做什么，例如：「分析这些资料，先给出四类推荐词表，再生成九大画像，输出 Markdown 文件。」
  5. 豆包若追问缺项（案例、政策、资质等），有事实就补上；没有就直接回复「没有」或「待补」，不要让它自己编。
  6. 下载它生成的交付文件（如推荐词表、垂直画像 Markdown）；需要改某一块时说「只改第 X 部分」。
  7. 可按它提示选下一步：补全画像、导出缺失资料清单、或换下一家企业（建议新开对话）。
  • 缺资料时保留「待补 / 缺失」，不要虚构客户、案例、资质或排名。
  • 换企业或换项目时新开对话，避免两家资料混在一起。

06 / OUTPUT

你会得到

  • 企业 GEO Profile 与证据记录
  • 关键词矩阵、九大画像与垂直画像
  • 内容矩阵、发布策略、验证结果与缺口队列

07 / REQUIREMENTS

使用前确认

  • 企业事实与结论需要可验证来源；缺失信息必须明确标注。
  • 完整执行需要按 INDEX.md 路由读取仓库中的 schemas、workflows、templates 与 references。
  • 任何客户语料库读取、创建或更新均需遵守正式入口中的确认规则。
